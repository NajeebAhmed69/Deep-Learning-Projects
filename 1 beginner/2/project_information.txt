==========================================================
CUSTOMER CHURN PREDICTION PROJECT
Deep Learning with TensorFlow, Keras, and Streamlit
==========================================================

1. PROJECT TITLE
----------------
Customer Churn Prediction using Artificial Neural Networks

This project predicts whether a telecom customer is likely to
leave the service (churn) or remain a customer.

The model estimates a churn probability for each customer.
A decision threshold converts that probability into a final
prediction:

    Churn probability >= threshold  ->  Predict: Churn
    Churn probability <  threshold  ->  Predict: No churn

==========================================================

2. BUSINESS PROBLEM
-------------------
Customer churn is a major problem for subscription-based
businesses such as telecom companies. When a customer leaves,
the company loses future revenue and must spend money to
acquire a replacement customer.

The goal of this project is to identify customers who are
likely to churn so that the company can take early action,
such as offering discounts, improving service, or contacting
the customer with a retention offer.

Business question:

    Can we identify customers with a high risk of churn
    before they leave?

6. DATA PREPROCESSING
---------------------
The following preprocessing steps were performed:

1. Removed customerID because it is only an identifier and
   does not describe customer behavior.

2. Converted TotalCharges from text/object type to numeric
   type using pd.to_numeric().

3. Handled missing TotalCharges values. In this dataset,
   missing values are commonly associated with customers who
   have zero tenure. Therefore, missing TotalCharges values
   were filled with 0.

4. Converted the target variable:

       No  -> 0
       Yes -> 1

5. Separated features (X) and target (y).

6. Split the dataset into:

       Training set:   60%
       Validation set: 20%
       Test set:       20%

7. Used stratified splitting to preserve the churn/non-churn
   class ratio in each set.

8. Applied StandardScaler to numerical features.

9. Applied OneHotEncoder to categorical features.

Important rule:
    The scaler and encoder were fitted only on the training
    data. The validation and test sets were transformed using
    the already-fitted preprocessing pipeline.

This prevents data leakage.

==========================================================

7. DATA SPLITTING
-----------------
The data was divided into three parts:

    Training set:
        Used to fit preprocessing and train models.

    Validation set:
        Used to monitor ANN training and select the
        classification threshold.

    Test set:
        Used only once for final evaluation.

This approach prevents the test set from influencing model
selection or threshold selection.

==========================================================

8. DEEP LEARNING MODEL
----------------------
An Artificial Neural Network (ANN) was built using Keras.

Model architecture:

    Input layer
        |
        v
    Dense layer: 64 neurons, ReLU activation
        |
        v
    Dropout layer: 30%
        |
        v
    Dense layer: 32 neurons, ReLU activation
        |
        v
    Dropout layer: 20%
        |
        v
    Dense layer: 1 neuron, sigmoid activation

Output:
    A single probability between 0 and 1.

Example:
    0.83 means the model estimates an 83% chance that the
    customer will churn.

The final Dense layer uses sigmoid activation because this is
a binary classification problem.

==========================================================

11. DECISION THRESHOLD
----------------------
By default, a model may predict churn when the probability is
at least 0.5.

However, the best threshold depends on the business goal.

    Lower threshold:
        More customers are predicted as churners.
        Higher recall.
        More false positives.

    Higher threshold:
        Fewer customers are predicted as churners.
        Higher precision.
        More false negatives.

In this project, the threshold was selected using validation
data by testing thresholds from 0.10 to 0.90 and choosing the
threshold with the highest F1-score.

The selected threshold was then used for final test-set
evaluation.

==========================================================

12. MODEL EVALUATION
--------------------
The following metrics were used:

Accuracy:
    The percentage of all customers classified correctly.

Precision:
    Of all customers predicted as churners, how many actually
    churned?

Recall:
    Of all customers who actually churned, how many did the
    model detect?

F1-score:
    Balance between precision and recall.

PR-AUC:
    Measures how well the model ranks churners above
    non-churners. It is useful for imbalanced datasets.

Confusion matrix:
    Shows correct and incorrect predictions for each class.

Error types:

    False positive:
        Model predicts churn, but the customer stays.

    False negative:
        Model predicts no churn, but the customer churns.

For churn prevention, false negatives can be costly because
the company misses an opportunity to retain a customer.

==========================================================

13. MODEL COMPARISON
--------------------
Three models were compared:

1. Artificial Neural Network (ANN)
2. Logistic Regression
3. XGBoost Classifier

All models used the same training data, validation data, test
data, preprocessing pipeline, and decision threshold.

The purpose of the comparison was to determine whether the
neural network adds value over classical machine-learning
models.

Important note:
    Deep learning does not always outperform classical machine
    learning. For small, structured tabular datasets, XGBoost
    and logistic regression can be very strong baselines.

19. LIMITATIONS
----------------
1. The dataset is a snapshot, so the model predicts churn risk
   based on available historical features. It does not
   guarantee that a customer will churn.

2. The dataset is imbalanced, so accuracy alone can be
   misleading.

3. The ANN may not outperform XGBoost on this tabular dataset.

4. The model should be retrained periodically when new customer
   data becomes available.

5. The Streamlit app should use the same preprocessing pipeline
   and feature names used during training.
